# Family unions API

Статус: реализованный контракт Этапа 7. Все пути имеют префикс `/api/v1`, требуют Bearer access token и ограничены активным membership указанного дерева.

## Инварианты

- союз принадлежит одному дереву и содержит от `2` до `10` уникальных активных персон этого дерева;
- первичный союз и все его участники создаются в одной PostgreSQL-транзакции;
- `owner` и `editor` изменяют союз, `viewer` только читает;
- outsider получает `404`, даже если знает UUID дерева, союза или персоны;
- составные внешние ключи не позволяют связать союз с персоной другого дерева;
- изменение полей и состава увеличивает `version`; update/delete используют optimistic version;
- удалённый союз не попадает в чтение и граф.

Доступные типы: `marriage`, `civil_union`, `partnership`, `engagement`, `unknown`. Пустой тип при создании преобразуется в `unknown`.

## Создать союз

`POST /trees/{treeID}/unions`

```json
{
  "type": "marriage",
  "note": "Запись из метрической книги",
  "members": [
    {
      "person_id": "f6cc2452-246a-41f2-a025-80259fe03ab3",
      "role": "spouse"
    },
    {
      "person_id": "75c8b77a-97aa-47aa-8791-697369ce837e",
      "role": "spouse"
    }
  ]
}
```

Ответ: `201 Created`, начальная версия равна `1`.

## Получить союз

`GET /trees/{treeID}/unions/{unionID}`

```json
{
  "union": {
    "id": "342f2a90-8656-4a23-9034-2f7964832764",
    "tree_id": "3f7e35d0-35b5-46f9-be4a-6d388cf05a32",
    "type": "marriage",
    "end_reason": "",
    "note": "Запись из метрической книги",
    "created_by": "0c1a433b-8879-420b-85bc-0028dc29451f",
    "updated_by": "0c1a433b-8879-420b-85bc-0028dc29451f",
    "created_at": "2026-08-20T18:00:00Z",
    "updated_at": "2026-08-20T18:00:00Z",
    "version": 1
  },
  "members": [
    {
      "person_id": "f6cc2452-246a-41f2-a025-80259fe03ab3",
      "role": "spouse",
      "created_at": "2026-08-20T18:00:00Z"
    }
  ],
  "access": {
    "role": "owner",
    "status": "active"
  }
}
```

## Изменить союз

`PATCH /trees/{treeID}/unions/{unionID}`

```json
{
  "version": 1,
  "type": "civil_union",
  "end_reason": "Уточнено по архивной записи",
  "note": "Проверено исследователем"
}
```

Изменяемые поля: `type`, `end_reason`, `note`. Устаревшая версия возвращает `409 Conflict`.

## Добавить участника

`POST /trees/{treeID}/unions/{unionID}/members`

```json
{
  "person_id": "f7eca146-c94c-46e7-8ca2-e26805a0503c",
  "role": "member"
}
```

Ответ: `200 OK` с обновлённым агрегатом и увеличенной версией союза. Повторный участник возвращает `409`, превышение десяти участников — `422`.

## Удалить участника

`DELETE /trees/{treeID}/unions/{unionID}/members/{personID}`

Ответ: `200 OK` с обновлённым агрегатом. Удаление, после которого осталось бы меньше двух участников, возвращает `422`.

## Удалить союз

`DELETE /trees/{treeID}/unions/{unionID}`

```json
{
  "version": 4
}
```

Ответ: `204 No Content`. Удаление мягкое, увеличивает версию и транзакционно создаёт `family_union.deleted` в `audit_log`.

## Ошибки

- `400` — некорректный UUID, тип, роль или тело запроса;
- `401` — отсутствует действительный access token;
- `403` — Viewer пытается изменить союз;
- `404` — дерево, союз, участник или персона отсутствуют либо недоступны;
- `409` — повторный участник или устаревшая версия;
- `422` — нарушены ограничения количества участников.

Даты начала/окончания, места и связи с архивными документами добавляются следующими расширениями домена после базового жизненного цикла.
